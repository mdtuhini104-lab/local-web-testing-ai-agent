## 2026-03-30 - SQLite Database Indexing and WAL Mode Performance
**Learning:** Without explicit secondary indexes on `test_steps(run_id)` and `test_runs(created_at DESC)`, SQLite query execution for `get_test_run_details` and retention pruning performs full table scans $O(N)$ across all recorded steps in the database. Adding index `idx_test_steps_run_id` reduces query latency from $O(N)$ to $O(\log N)$, providing a >3.3x speedup on step lookups. Furthermore, enabling `PRAGMA journal_mode=WAL;` prevents database write lock contention when logging live test steps concurrently with live websocket broadcast and UI reads.
**Action:** Always ensure foreign keys and foreign query parameters in SQLite tables (like `run_id` in step logs) have dedicated B-tree indexes, and enable WAL mode on initialization for concurrent async IO workloads.
